## Features

- Responsive storefront and product catalogue
- Product details, shopping bag, and checkout
- Customer registration, login, and profile
- Reviews and order tracking
- Admin pages and reporting endpoints
- M-Pesa Daraja STK Push integration with callback handling

## Tech stack

- Node.js and Express serve the site and API
- Static frontend files are in `public/`
- API routes are in `routes/`; shared utilities are in `utils/`
- M-Pesa integration uses Safaricom Daraja
- The app stores users, products, orders, reviews, and payments in PostgreSQL when `DATABASE_URL` is set. Without it, local development falls back to JSON files.

## Run locally

Requirements: Node.js 20 or later and npm.

1. Clone this repository and open its directory.
2. Install dependencies:

   ```bash
   npm ci
   ```

3. Copy `.env.example` to `.env` and set a long, private `JWT_SECRET`. Add Daraja sandbox credentials only if you want to test M-Pesa. Never commit `.env` or real credentials.
4. Start the app:

   ```bash
   npm start
   ```

5. Open [http://localhost:5000](http://localhost:5000). Check [http://localhost:5000/api/health](http://localhost:5000/api/health) to confirm the server is responding.

## Deploy on Render

The repository includes `render.yaml` and a `Dockerfile` for a Render web service.

1. Push the project to GitHub.
2. In Render, choose **New → Blueprint** and connect this GitHub repository. Render should detect `render.yaml` and create the web service.
3. In the service's environment settings, provide Daraja values when needed: `MPESA_ENV`, `MPESA_CONSUMER_KEY`, `MPESA_CONSUMER_SECRET`, `MPESA_SHORTCODE`, `MPESA_PASSKEY`, and `MPESA_CALLBACK_URL`.
4. Create a PostgreSQL project, then add its connection URL to the service as `DATABASE_URL`. On its first startup, the app initializes the database and imports local JSON files if they exist in the deployed app.
5. Set `MPESA_CALLBACK_URL` to the public HTTPS URL followed by `/api/mpesa/callback`, for example `https://your-service.onrender.com/api/mpesa/callback`.
6. Keep `MPESA_ENV=sandbox` while using sandbox credentials. Switch to production only after Safaricom has issued production credentials and the callback is publicly reachable over HTTPS.
7. After deployment, open `/api/health` on the service URL. Its `database` field reports `postgres` when `DATABASE_URL` is configured. The app's `JWT_SECRET` is generated by the Blueprint configuration.

Free database plans can pause and may have limited backups or retention. Check your provider's current limits and export backups regularly before accepting real orders.

## Environment variables

See `.env.example` for the complete list. Common settings:

| Variable | Purpose |
| --- | --- |
| `PORT` | Local server port; hosting platforms may set this automatically. |
| `JWT_SECRET` | Private signing secret for login sessions. |
| `DATABASE_URL` | PostgreSQL connection URL; when unset, local JSON storage is used. Keep it private. |
| `MPESA_ENV` | `sandbox` or `production`. |
| `MPESA_CONSUMER_KEY` / `MPESA_CONSUMER_SECRET` | Daraja application credentials. |
| `MPESA_SHORTCODE` / `MPESA_PASSKEY` | Daraja shortcode and STK passkey. |
| `MPESA_CALLBACK_URL` | Public HTTPS URL for `/api/mpesa/callback`. |
